# 可选深度数据包（默认不装）

## 1. 为什么是「可选」

agent 的**门类内核已经嵌在提示词里**（判读规则表、查表、决策流程），
所以**不装数据包也能完成门类判读**——这是设计的正常状态。

数据包提供的是**更细的逐条目、逐表格资料**（例如手相按线纹逐条、八字按干支关系逐条）。
它属于「深度参考」，不是「能否运行」的问题。

## 2. 为什么不随仓库分发

数据包内容来自《世界相命全集》的正文与 OCR 底稿，**版权归原作者与出版方**。
因此本仓库只提供**构建脚本**，由你**用自己合法持有的底稿**在本地生成。见 `../NOTICE.md`。

## 3. 构建流程

```bash
# 1) 准备你自己的源（扫描 PDF 或已有 OCR 文本）
# 2) 若为扫描件，先用任一 OCR 工具转成 markdown，每册一个文件
# 3) 用脚本把底稿整理成数据包骨架
python tools/build_datapack.py --sources <你的底稿目录> --out <数据包目录>
```

脚本会：

1. 校验底稿文件命名与册序，生成 `sources/` 与 `docs/PROVENANCE.md`
2. 按 `spec/SPEC-蒸馏规范.md` 生成**待蒸馏清单**（每门类一份骨架）
3. 打印每个门类需要填充的目标路径

**蒸馏步骤需要 LLM 参与**（归纳判读规则、建表、标注三层 provenance），
本仓库不联网、不内置模型，请在你自己的模型环境里按 `spec/SPEC-蒸馏规范.md` 完成。

## 4. 数据包目录约定

```
<数据包目录>/
├── kb/<门类>/<门类>-判读条目.md     ← 逐条目深度资料（agent 按此固定路径直读）
├── kb/_SPEC-蒸馏规范.md
├── sources/<册名>.md                ← 你自己的 OCR 底稿（供典籍校勘回溯页码）
├── docs/OVERVIEW.md
├── docs/PROVENANCE.md
└── assets/<册>/fig-NN-NNN.jpg       ← 可选：插图
```

装好后让 agent 找到它：安装时传 `--datapack-root <数据包目录>`，
脚本会把 agent 里的 `{{DATAPACK_ROOT}}` 替换成该路径。

## 5. 降级行为（重要）

未装数据包时，agent 必须：

- 仍然**完全依据内核作答**；
- **不得声称读过深度条目**，不得编造条目细节；
- 用户要极细条目时，如实说明「需要安装可选深度数据包」；
- 典籍校勘代理**无法回溯页码**，须明确声明。

若你的 agent 未装数据包却「引用了」深度条目，那是**编造**，属于 bug。
